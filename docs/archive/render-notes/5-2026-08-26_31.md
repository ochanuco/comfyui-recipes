### 根本原因: negative は凍結された過去の修正の要塞で、誰も読み返さない (2026-08-27)

膝枕深掘りで同じ形の事故が繰り返された。sheer を頼んだ 6 アームの色崩壊、
水色背景の指定が「無視」された件、その代償に選んだ後処理の範囲ぐちゃぐちゃ。
並べると一つの構造に還元される:

**positive の新しい要求が、別の見た目のために昔立てた negative の ban と
衝突している。** sheer は `(transparent clothing:1.3)` に、"もっと薄く" は
`(black pantyhose)` の重みと `(dark)` に、水色背景は `(blue background:1.5),
(blue tint:1.4)` に、それぞれ正面からぶつかっていた。ban は一度入ると全アーム
に黙って継承され、衝突してもエラーは出ない — 絵が壊れて初めて分かる。
8921 行の「Guarding a property while banning the fix」と同じ病で、今回は
それが3連発した。逃げ場を全部塞がれたモデルが緑に逃げてセージ背景と
カーキタイツになったのも同根。

**解決はコードに置いた。** `scripts/prompt_lint.py` が positive と negative
の矛盾（同じ色・素材・対象の両面指名、sheer vs transparent 系、色付き背景
vs 色 ban）を検出し、`generate.py` は explicit prompt の request で矛盾が
あると停止する（意図的なペアは `--force`）。素のレシピは全 costume × 全

### 線画→肌だけ着色: 決定的合成の一連 (2026-08-27)

7uo0bm の good（9g298c）を材料に、レイヤー分離パイプラインの着彩工程を
diffusion なしの決定的合成で試した一連。線画抽出は n0sanc（AnimeLineArt
3oo3r1 / LineartStandard 5s4dcr）、肌塗りは qxdyry → 2dpzyg → r3hwa9(顔のみ)
→ ayi9z2 → 7u1emv。形は「マスク抽出は Claude 側・合成は graph」。

- **線画抽出器の出力は二値ではない。** AnimeLineArt は soft shading をグレー
  階調で持ち、multiply 合成すると全体が薄塗りに見える（qxdyry の欠陥）。
  二値化ランプで解決するが、しきい値は抽出器ごとに違う — AnimeLineArt は
  0.45-0.75、LineartStandard は 0.35-0.70。
- **このレシピのパレットは色を使い回しており、色だけでは部位を分離できない。**
  肌の地色 (248,240,240)・手の肌 (248,240,248)・髪ハイライト (248,240,248)・
  白フチ (248,248,248) が近接ないし同一。肌マスクは色クラスタ
  （R≥240, R−G 5〜48）と空間領域の組で作り、髪に隣接する眉上の帯だけ
  B≤244 の厳格条件を足した。サイドロック際のにじみは残る（線画が上に
  乗る下塗りとしては許容）。頬に触れた指は顔と連結していて分離不能。
- **肌の地色はほぼ白で、単色下塗りは白地の上で知覚できない。** #f8f0f0 は
  白との差が RGB (7,15,15)。元絵で肌に見えるのは頬紅・影・水色背景との
  相対差による。見える肌レイヤーが欲しければ元絵画素のマスク切り出し
  （7u1emv）— base+shadow+highlight を1層に畳んだ形で、工程分解の続きは
  この層を割ること。
- 9g298c の可視肌は顔・首・両手のみ（脚は全面タイツ）。マスク面積は
  画面の 3.6%。

### ペン入れは引き直し、マスクは watertight (2026-08-28)

工程が一本つながった: 下書き（ヒステリシス二値化）→ ペン入れ → 着色。
9g298c 系: reink 3腕 suxlos → 着色 nk9rq6 → 修正 h79imy。natn74 系:
reink ilkpmu。

- **ペン入れの定義を取り違えていた。** ラスタ平滑化（3ene71 の 2x+ガウス+
  smoothstep）は「均一幅の丸ペン」にしかならず棄却。正しくは下書きを
  破棄して線を引き直すこと — 二値化下書きを latent に encode し、hassaku に
  monochrome/lineart 指定の img2img（denoise 0.40/0.55/0.70 の3腕）で
  引かせると、入り抜き・線幅の抑揚・ハッチの筆致が本物のストロークで出る。
  0.55 が「下書きの構造を保ちつつ筆致が出る」の中庸。ControlNet 不要。
  トレードオフ: 目・口など細部の解釈は下書きからドリフトする。
- **色ルールのマスクは境界を必ず取り逃す。** nk9rq6 では図の 7.5% が
  どのレイヤーにも属さず白く残った（アンチエイリアスの中間トーン）。
  修正は watertight 化: 縁から背景+白フチを flood して外界を確定し、
  図領域内の未割り当て画素を距離変換の最近傍レイヤーに吸着させて
  完全分割にする。残ギャップ 0。今後マスクを作るときは最初からこれを通す。
- 線画抽出の既知条件（再掲を避ける）: ネイティブ解像度で抽出し、
  ヒステリシス（強 0.55 / 弱 0.28 連結）で二値化してから使う。

### 局所再生成の3プローブ: 外は同一、色は強制、形はまだ (2026-08-28)

Semantic Spec（tights=#18181c、socks=#b7a4d8、socks above tights）を 9g298c
に対して3方式で実測した。socks はどのレンダーにも存在せず、layer graph に
定義して作った領域（脛〜足首帯）。

- Crop&Stitch 素（pu232u、denoise 0.75）: `ComfyUI-Inpaint-CropAndStitch`
  導入。**マスク外 max diff 0 を numpy で確認** — 「マスク外は VAE を

socks マスクを作ってから。

(two-tone legwear:1.4) 等を ban しており、socks 系の実験では外さないと
黙って衝突する（negative-bans-outlive-their-look の再演）。

## 2026-08-31 表情差分シート: 目のタグが顔の色を決めていた、そして納品が3つ壊れていた

胸像の表情差分（目3種 × 口3種、`portrait` の framing、seed 42 と
1188654301 を9腕で共有）を刷る過程で、目軸のタグが表情ではなく figure 全体の
色相を決めていることが出た。付随して納品側の欠陥が3つ見つかっている。

### 目のタグが肌の色を決める

同じポーズ・同じ衣装・同じ seed で目のタグだけを変えたとき、生レンダーの
明部（figure, V>=150, S>20）の肌色相（PIL H 0-48）の占める割合:

| 目軸 | seed 42 | seed 1188654301 |
|---|---|---|
| ドヤ `(half-closed eyes:1.3)` | 81.0% | 61.7% |
| 素顔 `(unamused:1.3)` 併記 | 2.1% | 0.2% |
| 眠気 `(sleepy:1.35)` 併記 | 10.0% | 0.8% |

参照 stand 4eqpdv は 78.7%。つまり素顔と眠気は顔が紫で描かれていて、明部の
83〜93% が紫色相にある。`unamused` は 2026-08-28 に FACE のデフォルト
（`RESTING_EYES`）として標準化された語なので、これは表情シート限りの話では
ない。

### ガードは pass 1 でしか効かない

`(colored skin:1.45)` を第2パスの negative に置くと肌は 0.2% → 46.5% に戻る
が、髪と瞳の紫も一緒に抜けてキャラがグレーになる。同じタグを第1パスの
negative 先頭に置くと肌 2.1% → 66.8%、figure 彩度は 34.0 → 29.6 の微減で紫は
残る。AGENTS.md の「ガードは削除であり、第1パスは同じガードの周りで構図を
組み直す」がそのまま出た形。

同じ軸で外れたもの: 第2パス positive の `(fair skin:1.4)` は完全に無反応
（0.2% → 0.2%）。finalize の denoise を 0.45 / 0.35 に下げると肌色 share は
上がるが、それは figure 全体が退色して基準が下がっただけで紫を失う。
**肌色 share は退色でも上がる指標なので、単独では採否の根拠にならない。**

### 納品のシルエットは色から切ってはいけない

delivery の背景 flood は figure が 85% を占める胸像で背景を 44% と誤り、
ダイカットの縁を前髪と横髪の中に引いていた。犯人は repin で、accent 帯の圧縮が
淡ラベンダーの髪を corner seed との色差18以内へ寄せる。生レンダーの flood は
正確（BiRefNet の matte と 0.2% 差）で、壊れるのは repin の後だけ。

シルエットは絵の性質であって着色処理の結果ではないので、matte を色から切り
離した。ComfyUI 0.33 コアの `LoadBackgroundRemovalModel` / `RemoveBackground`
（`birefnet.safetensors`）を 2048 チェーンと同じ submission に載せ、
`fin-<id>-matte` として保存する。`clean_background` はそれを必須引数で受ける。

四隅の平坦ゲートは撤去した。守っていた flood が delivery に無くなったため。
`palette_check` は今も flood 経由で測るので、そちらのスクリーンとしては残る。

### 補正は、補正対象が無いときに引き算しかしない

pass 1 のガードで生成がバンド内に入ると、バンドへ引き戻すための機構が害に
なる。ガード付きレンダーの素通し納品は単独で pass する（sat 38.2、figure mid
31.9）。そこに掛けると:

- repin は figure p90 を 72 → 53 に削り、虹彩を灰にする。accent ramp が絶対
  彩度 150 始まりで、このレンダーの虹彩は S≈145 と閾値に届かないため保護
  されない。`delivery_style.py` のコメントは「accent はどのフィールドの彩度
  よりも十分高い」と相対で書いてあるが、コードは絶対値で固めている。
- 肌ピンは、再描画の肌領域がすでに 100% 肌色相なのに 8〜22% の面積で発火し、
  顔と胸にオレンジのムラを作る。

`--no-skin` を `--no-repin` と対で足した。ガード付きの家族は両方外して納品する。

### 肌ピン自体の2つのバグ

色相は円環。紫(191)から肌(18)へ減算で寄せるとフェザーの中間値が緑(85付近)を
通り、顔の輪郭と顔を横切る毛束すべてに緑の縁が出る。短い側を回ること。

base が顔をラベンダーで描いたコマではマスクに顔ではなく斑点しか残らず、それを
塗るとクリームのムラになる。面積が下限を割ったらピンを打たない。**納品は base
が描いた肌を戻す機構であって、描かれなかった肌を作る機構ではない。**

### 採用

ガード付き9腕2seed の18枚を、matte 切り抜き + 背景 + 縁だけで納品したものが
人間の採用（「おお！改善しましたね！これでいきましょう」）。delivery
fingerprint は b7e49ee3d5a63088 → 87dfd2e97619ecd0。

pass 1 のガードはまだアーム側の patch で、`NEGATIVE` には入れていない。根拠が
`portrait` の頭部 framing 18枚に限られ、全身ポーズの脚とタイツに
`colored skin` が何をするかは未測定のため。

残る既知の穴: 目軸のタグはカメラ距離も動かしていて、ドヤ行だけ顔が小さく
背景の余白が広い。格子として厳密な比較になっていない。
